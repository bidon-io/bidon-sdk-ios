# Zhenya Ad Caching — Документация

## Обзор

Zhenya Ad Caching (strategy = 1) — стратегия кеширования рекламы, при которой результаты аукциона накапливаются в кеше и переиспользуются при последующих вызовах `loadAd()`. Это позволяет мгновенно отдавать рекламу из кеша без повторного аукциона и автоматически заполнять кеш в фоне.

Стратегия применяется для всех форматов: **Interstitial**, **Rewarded** и **Banner**.

---

## Конфигурация

Конфигурация задаётся для каждого формата отдельно (banner, interstitial, rewarded):

| Параметр | Диапазон | По умолчанию | Описание |
|----------|----------|--------------|----------|
| `cacheSize` | 1–10 | 1 | Максимальное количество элементов в кеше |
| `noFillDelayMs` | 2000–64000 | 2000 | Задержка перед повторным запросом при отсутствии рекламы |
| `strategy` | 0, 1, 2 | 0 | Стратегия кеширования (1 = Zhenya) |

---

## Основная идея

Стандартный аукцион: `loadAd()` → аукцион → одна победившая ставка → `show()`.

Zhenya-кеширование: `loadAd()` → аукцион → **все** успешные ставки складываются в кеш → `show()` берёт лучшую из кеша. При следующем `loadAd()` реклама может быть отдана мгновенно, если в кеше уже есть подходящая ставка.

---

## Кеш

### Структура

Кеш — это упорядоченный массив ставок (bids), отсортированных по цене от большей к меньшей. Ёмкость задаётся через конфигурацию (`cacheSize`). Для каждого формата — отдельный экземпляр кеша.

### Операции

| Операция | Описание |
|----------|----------|
| **peek** | Посмотреть лучшую (первую) ставку, не удаляя из кеша |
| **pop** | Извлечь лучшую ставку из кеша (удаляет) |
| **insert** | Вставить ставку в кеш с сохранением сортировки |
| **beginIteration** | Сбросить ценовой трекер перед новым аукционом |

### Sticky-режим

Когда аукцион возвращает первую ставку, она вставляется в кеш как **sticky** — фиксируется на первой позиции (index 0). Остальные ставки аукциона вставляются как обычные.

Зачем: первая ставка — это то, что пользователь ожидает увидеть по результату `loadAd()`. Она должна быть гарантированно доступна при вызове `show()`, даже если последующие ставки с более высокой ценой сдвинут её при обычной сортировке.

```
Sticky mode:  [LOCKED]  [sorted by price ↓]  [sorted by price ↓]  ...
Normal mode:  [sorted by price ↓]  [sorted by price ↓]  [sorted by price ↓]
```

- Sticky-элемент **не может быть вытеснен** другими ставками.
- При вызове `pop` sticky-режим **снимается** — кеш возвращается к обычной сортировке.

### Ценовой порог (50%)

При `cacheSize > 1` кеш отслеживает максимальную цену в текущей итерации аукциона. Ставки ниже **50%** от максимальной цены **отклоняются** — это предотвращает заполнение кеша низкокачественной рекламой.

```
Пример: максимальная цена в итерации = $10
  $7.00 (70%) — принято
  $5.00 (50%) — принято
  $4.99 (49.9%) — отклонено
```

### Вытеснение

Когда кеш заполнен и приходит новая ставка:

1. Определяется самый дешёвый элемент (последний в массиве, кроме sticky)
2. Если новая ставка **дороже** вытесняемого — замена происходит
3. Если **дешевле** — новая ставка отклоняется

## Пул менеджеров

### Проблема

Рекламный объект (Interstitial/RewardedAd) создаётся и уничтожается вместе с экраном. Но менеджер, который управляет аукционом и кешем, должен жить дольше — иначе кеш теряется при каждом переходе между экранами.

### Решение

Глобальный пул хранит менеджеры **независимо** от рекламных объектов.

- **Ключ** — `auctionKey` (строка, идентификатор плейсмента)
- **Один менеджер на ключ** — при создании нового рекламного объекта с тем же ключом возвращается существующий менеджер со всем накопленным кешем
- Пул держит **сильную ссылку** на менеджер, **слабую** — на рекламный объект

### Автоочистка

Раз в **60 секунд** пул проверяет менеджеры и удаляет те, которые:
1. В состоянии покоя (idle)
2. Простаивают более **5 минут**
3. Не имеют связанного рекламного объекта (слабая ссылка == nil)

Все три условия должны выполняться одновременно.

### Баннеры

Для баннеров используется аналогичный подход: один менеджер на placement. Пул менеджеров не нужен, т.к. баннерный view обычно живёт на экране постоянно.

---

## Алгоритм загрузки (loadAd)

```
loadAd(pricefloor)
  │
  ├── Заглянуть в кеш (peek)
  │     │
  │     ├── Есть ставка и цена >= pricefloor?
  │     │     → Отдать рекламу немедленно (без аукциона)
  │     │     → Уведомить делегат: "реклама загружена"
  │     │     → КОНЕЦ
  │     │
  │     └── Кеш пуст или цена < pricefloor
  │           → Запустить аукцион (см. ниже)
  │
  └── Аукцион
        │
        ├── Сбросить ценовой трекер итерации (beginIteration)
        ├── Установить флаг: isFirstBid = true
        │
        └── Для каждой успешной ставки по мере поступления:
              │
              ├── Вставить в кеш (sticky: isFirstBid)
              │
              ├── Если isFirstBid:
              │     ├── Уведомить делегат: "реклама загружена"
              │     └── isFirstBid = false
              │
              └── Иначе: молча положить в кеш
                  (остальные ставки кешируются в фоне)
```

**Ключевое отличие аукциона:** стандартный аукцион ждёт завершения всех demand-источников и возвращает лучшую ставку. Аукцион для Zhenya-кеширования вызывает колбэк **для каждой ставки** по мере поступления — первая ставка отдаётся пользователю, остальные молча заполняют кеш.

---

## Алгоритм показа (show)

```
show()
  │
  ├── Извлечь лучшую ставку из кеша (pop)
  ├── Создать impression из закешированной ставки
  └── Показать рекламу
```

---

## Баннеры: отличия

Логика аналогична fullscreen, с одним дополнением:

- Перед каждым новым `loadAd()` вызывается **prepareForReuse**, который делает `pop` из кеша — это убирает текущий показанный баннер, чтобы при следующей загрузке отдать новый.

---

## Потокобезопасность

- **Кеш** — защищён мьютексом (lock). Все операции (insert, peek, pop) атомарны.
- **Пул менеджеров** — concurrent queue с барьерами для записи (reader-writer lock).
- **Колбэки делегату** — всегда на главном потоке.

## Полный пример жизненного цикла

```
1. Конфигурация: strategy = 1, cacheSize = 5

2. Создаётся рекламный объект с ключом "main_screen"
   → Пул создаёт менеджер для этого ключа

3. loadAd(pricefloor: 0.5)
   → Кеш пуст → запускается аукцион
   → Ставка $3.00 от AdMob  → insert(sticky) → делегат: "загружено"
   → Ставка $2.80 от Unity  → insert         → молча в кеш
   → Ставка $1.20 от Vungle → insert         → молча в кеш

   Кеш: [$3.00*] [$2.80] [$1.20]    (* = sticky)

4. show()
   → pop → $3.00 (sticky снимается)
   → Показ рекламы

   Кеш: [$2.80] [$1.20]

5. loadAd(pricefloor: 0.5)
   → peek → $2.80 >= 0.5
   → Делегат: "загружено" (мгновенно, без аукциона!)

6. show()
   → pop → $2.80
   → Показ рекламы

   Кеш: [$1.20]

7. Рекламный объект уничтожен (экран закрыт)
   → Менеджер остаётся в пуле
   → Кеш сохраняется

8. Создан новый рекламный объект с тем же ключом "main_screen"
   → Пул возвращает существующий менеджер
   → Кеш: [$1.20] — всё ещё доступен

9. loadAd(pricefloor: 0.5)
   → peek → $1.20 >= 0.5
   → Делегат: "загружено" (мгновенно!)

10. Через 5 минут без активности и без рекламного объекта
    → Автоочистка удаляет менеджер
```
